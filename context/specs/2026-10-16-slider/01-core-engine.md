### 3. Stylesheet `src/styles.css`

Every selector wrapped in `:where()` (zero specificity). Exactly:

```css
:where([data-slider-viewport]) {
  position: relative;
  display: flex;
  gap: var(--slider-gap, 0px);
  overflow-x: auto;
  overflow-y: hidden;
  overscroll-behavior-x: contain;
  scroll-snap-type: x mandatory;
  scrollbar-width: none;
}
:where([data-slider-viewport])::-webkit-scrollbar {
  display: none;
}
:where([data-slider-viewport][data-axis='y']) {
  flex-direction: column;
  overflow-x: hidden;
  overflow-y: auto;
  overscroll-behavior-x: auto;
  overscroll-behavior-y: contain;
  scroll-snap-type: y mandatory;
}
:where([data-slider-viewport]) > * {
  flex-shrink: 0;
  flex-basis: calc(
    (100% - (var(--slider-per-view) - 1) * var(--slider-gap, 0px)) / var(--slider-per-view)
  );
  min-width: 0;
  min-height: 0;
  scroll-snap-align: var(--slider-align, start);
}
```

When `--slider-per-view` is unset the `calc()` is invalid at computed-value time, `flex-basis`
falls back to `auto`, and slides size themselves — that is the "auto" per-view mode, deliberately.
The default `scroll-snap-align` is what makes the layout snap before JavaScript runs; the engine
overrides it inline per slide.

### 4. Public types — `src/core/types.ts`

```ts
import type { Axis, ScrollAnimation } from 'use-scroller/core'

export type { Axis, ScrollAnimation }
export type Align = 'start' | 'center' | 'end'

export interface SliderOptions {
  axis?: Axis                       // default 'x'
  align?: Align                     // default 'start'
  slidesPerMove?: number | 'auto'   // default 1; a number must be an integer >= 1 (else RangeError)
  loop?: boolean                    // default false (unit 02 implements it)
  rewind?: boolean                  // default false; ignored when loop is active
  draggable?: boolean               // default true
  startIndex?: number               // default 0; clamped into range on first measure
  animation?: ScrollAnimation       // default for navigation; default { type: 'tween' }
}

export interface SliderState {
  index: number        // active snap index (target index while a navigation is pending)
  snapCount: number
  slideCount: number   // real slides only
  canPrev: boolean
  canNext: boolean
  progress: number     // 0..1 along the snaps (see change 6)
  loopCopies: number   // copies of the slide set needed on each side; 0 unless loop (unit 02)
}

export interface NavigateOptions {
  animation?: ScrollAnimation       // overrides SliderOptions.animation for this call
}

export interface Slider {
  readonly viewport: HTMLElement
  readonly options: Readonly<Required<Omit<SliderOptions, 'startIndex'>>>
  getState(): SliderState
  subscribe(listener: (state: SliderState) => void): () => void
  next(options?: NavigateOptions): void
  prev(options?: NavigateOptions): void
  scrollTo(index: number, options?: NavigateOptions): void
  destroy(): void
}
```

`subscribe` does not call the listener immediately; it is called after every state change (a new
state object each time; unchanged fields keep their values). `getState()` returns the same object
until something changes. `scrollTo` throws `RangeError` for a non-integer index; an out-of-range
integer is clamped (unit 02 makes it wrap in loop mode). All methods throw `Error('Slider was
destroyed')` after `destroy()`, except `destroy()` itself which is idempotent.

### 5. Geometry — `src/core/geometry.ts`

Two halves: one function that reads the DOM into plain data, and pure functions over that data.

**Reading** — `readLayout(viewport, axis): Layout`:

```ts
interface Box { start: number; end: number }          // scroll coordinates of the slide's edges
interface Layout {
  slides: HTMLElement[]          // real slides, DOM order
  clones: HTMLElement[]          // [data-slider-clone] children, DOM order (unit 02 uses)
  boxes: Box[]                   // one per real slide
  gap: number                    // px; computed column-gap (x) / row-gap (y); 'normal' → 0
  port: { size: number; paddingStart: number; paddingEnd: number }
  range: { min: number; max: number }   // from readScroll: x → [minX, maxX], y → [0, maxY]
  direction: 1 | -1              // d: -1 only for axis 'x' with computed direction 'rtl'
}
```

- Box for axis `x`: `start = el.offsetLeft`, `end = el.offsetLeft + el.offsetWidth`; axis `y`:
  `offsetTop`/`offsetHeight`. These are already scroll coordinates because the viewport is the
  offsetParent (in RTL the boxes of slides are negative, matching negative scrollLeft — verify this
  with the RTL test rather than trusting it).
- Port: `clientWidth`/`clientHeight`; padding = computed `scroll-padding-left/right` (or
  `-top/-bottom`) resolved like use-scroller's `resolvePadding` (`auto` → 0, `%` of the port size,
  else `parseFloat`). In RTL, "start" padding is the right one.
- `readLayout` throws `Error('Slider viewport must be positioned; add position: relative (the
  stylesheet does this)')` when the viewport's computed `position` is `static`. `createSlider`
  calls it immediately, so the error surfaces at creation.

**Pure functions** (exported from the module for the engine; not from the package):

- `alignedPosition(box, port, align, direction)` — scroll position that puts `box` at the aligned
  spot. With `a` = `align` mirrored when `direction === -1` (`start` ↔ `end`):
  `start → box.start - port.paddingStart'`, `end → box.end - (port.size - port.paddingEnd')`,
  `center → (box.start + box.end) / 2 - (port.paddingStart' + (port.size - port.paddingStart' - port.paddingEnd') / 2)`,
  where `paddingStart'`/`paddingEnd'` are the **physical** left/top and right/bottom paddings.
- `groupSize(layout, slidesPerMove)` — the number, or for `'auto'`: the count of consecutive
  slides from slide 0 whose union fits in `port.size - paddingStart - paddingEnd` (+0.5px
  tolerance), minimum 1.
- `anchors(slideCount, size, align)` — anchor slide index per group: groups are
  `[0..size-1], [size..2size-1], …` (last may be short); anchor = first (`start`), last (`end`),
  `Math.floor((first + last) / 2)` (`center`).
- `snapPositions(layout, anchorIndexes, align)` — non-loop: each anchor's aligned position clamped
  to `range`, then any position within 1px of the previous kept one is dropped. Returns positions
  in logical (slide) order.
- `nearestSnap(positions, p)` — index of the position closest to `p` (ties → lower index).
- `progressOf(positions, p)` — `0` when fewer than 2 positions; else
  `clamp01((p - positions[0]) / (positions[last] - positions[0]))` (works in RTL because numerator
  and denominator are both negative).

### 6. The engine — `src/core/slider.ts`

`createSlider(viewport: HTMLElement, options: SliderOptions = {}): Slider`.

**Setup, in this order**: validate `slidesPerMove`; resolve defaults; `measure()` (change 7);
jump instantly to the snap for `startIndex` (clamped) with
`viewport.scrollTo({ left|top: pos, behavior: 'instant' })`; start
`observeScroll(viewport, onScroll)`; a `ResizeObserver` on the viewport and every real slide;
a `MutationObserver(viewport, { childList: true })`; `dragScroll(viewport, { axis, mouse: true })`
when `draggable`; `pointerdown` on the viewport and `pointerup`/`pointercancel` on `window` to keep
a `pointerDown` flag (unit 02 needs it; set it up now).

**State** is recomputed by one function `update(position)` after every measure and every
`observeScroll` emission, using the latest `position = layout.direction`-agnostic raw scroll
coordinate (`state.x` or `state.y`):
- `index` = pending navigation's target index if one is pending, else `nearestSnap(snaps, position)`.
- `snapCount`, `slideCount = layout.slides.length`.
- `canPrev` = `snapCount > 1 && (rewind || index > 0)`; `canNext` = `snapCount > 1 && (rewind || index < snapCount - 1)`.
- `progress = progressOf(snaps, position)`.
- `loopCopies = 0`.
Emit to listeners only when at least one field differs from the current state.

**Navigation** — `next()` / `prev()` / `scrollTo(i)` all go through `navigate(targetIndex, options)`:
- `from = pending?.index ?? state.index`.
- `next`: `from < last` → `from + 1`; else `rewind` → `0`; else do nothing.
- `prev`: `from > 0` → `from - 1`; else `rewind` → `last`; else do nothing.
- `scrollTo(i)`: clamp to `[0, last]`.
- `navigate` (snap ownership, per Decisions Made): if snap is not already held, set inline
  `scroll-snap-type: none` on the viewport, remembering the previous inline value; set
  `pending = { index }`; call
  `animateScroll(viewport, axis === 'x' ? { x: snaps[index] } : { y: snaps[index] }, { animation: options?.animation ?? sliderOptions.animation })`;
  keep the returned handle as `current`; `update()` immediately (so `index` shows the target);
  on `handle.finished`, **only if `current` is still this handle**: clear `pending` and `current`,
  restore the inline `scroll-snap-type`, `update()` from the live scroll position.
- With `animation: { type: 'instant' }` the jump is synchronous and `finished` resolves on the next
  microtask — tests rely on that.

**Snap anchors**: after each measure, for each real slide set inline
`style.scrollSnapAlign = isAnchor ? align : 'none'`. `destroy()` removes the property from every
slide it touched.

### 7. Re-measure

`measure()`: `readLayout`, compute group size, anchors, snaps, apply snap-align styles,
re-observe slides with the ResizeObserver (unobserve removed, observe added). Called:
synchronously at creation; synchronously from the MutationObserver callback; synchronously from
the ResizeObserver callback. After a measure, **if nothing is moving** — no `pending`
navigation, `pointerDown` false, and the last `observeScroll` state had `isScrolling: false` —
jump instantly to `snaps[state.index]` (clamped to the new snap count) so the current slide stays
put through a resize or an insertion. Then `update()`.

Do not use `requestAnimationFrame` for measuring: MutationObserver callbacks are microtasks and
ResizeObserver callbacks run after layout, both before paint, so measuring there never flashes.

### 8. `destroy()`

Stops observeScroll, both observers, dragScroll, the window/viewport pointer listeners; cancels a
running navigation (`current?.cancel()`); restores inline `scroll-snap-type` if held; removes
inline `scroll-snap-align` from slides; clears listeners.

1. **Snaps one per slide** — width 300, 5 slides, perView 1, gap 0 → `snapCount 5`, `slideCount 5`,

2. **Index follows native scrolling** — same fixture; `viewport.scrollTo({ left: 600, behavior: 'instant' })`
   → polls to `index 2`, `progress 0.5`.
3. **next/prev/scrollTo** — `next()` → `scrollLeft 300`, `index 1`; `scrollTo(4)` → `scrollLeft 1200`,

4. **Rapid next builds on the pending target** — with the default tween animation, call `next()`

5. **Rewind** — `rewind: true`, at index 4 `next()` → `scrollLeft 0`; at 0 `prev()` → `scrollLeft 1200`;
   `canPrev` and `canNext` both true at the edges.
6. **End clamping merges snaps** — width 320, 10 slides, perView 3, gap 10 (slides 100px, step 110,
   max scroll 770) → `snapCount 8`; `scrollTo(7)` → `scrollLeft 770`.
7. **slidesPerMove: 'auto'** — same fixture → `snapCount 4`; snaps at 0, 330, 660, 770

8. **slidesPerMove: 2** — width 300, 6 slides perView 1 → `snapCount 3`; `next()` → `scrollLeft 600`.
9. **Anchors get inline scroll-snap-align** — fixture of case 8: slides 0, 2, 4 have
   `style.scrollSnapAlign === 'start'`, others `'none'`; after `destroy()` all are `''`.
10. **align: 'center'** — width 300, 5 content-sized slides of width 200 (no perView), gap 0:

11. **startIndex** — fixture 1 with `startIndex: 3` → `scrollLeft 900` right after creation;

12. **Vertical axis** — height 200, `axis: 'y'`, 4 slides perView 1 → `next()` → `scrollTop 200`.

15. **Inserting a slide re-measures** — append a 6th slide → polls to `snapCount 6`.
16. **subscribe** — listener not called on subscribe; called once with `index 1` after `next()`;

18. **Draggable** — with `draggable: true` the viewport gets inline `touch-action: pan-y pinch-zoom`;

## Watch out

- `verbatimModuleSyntax` is on: type-only imports must be `import type`.
- `eslint-plugin-react-refresh` only matters for `.tsx`; it will not flag the `.ts` files here.
- `observeScroll` emits **once synchronously on subscribe**; the engine's `onScroll` must tolerate
  being called before setup has finished (start it after the first measure).
- Fractional layouts round in `offsetLeft`/`offsetWidth`; keep test fixtures at integer pixel sizes
  so literal expectations hold.
- `animateScroll` only suspends snap when the computed `scroll-snap-type` is not `none`. Because
  the engine sets inline `none` first, `animateScroll` leaves snap alone — this is intended; do not
  "fix" it by letting both restore.
